## 1. Starting with Git

### 1-1. Signing Up on GitHub

**Step 1: Open the sign-up page.**

Go to **[github.com](https://github.com)** and click the **Sign up** button in the top-right corner and fill in the form.

**Step 2: Verify your email.**

GitHub will send a **6-digit code** to your email address.

**Step 3: Complete the setup.**

GitHub will ask a few optional questions. You can answer them or click **Skip personalization**. None of these choices affect your ability to use GitHub.

**Step 4: You are in.**

You will land on your GitHub dashboard. Your profile page is at `github.com/your-username`.

---

#### 1-1-a. Opening Your Project Repository

A **repository** (or "repo") is a folder for your project that lives on GitHub.

**Creating your own repository.**

1. Click the **+** icon in the top-right corner of GitHub, then choose **New repository**.
2. Give it a name (e.g., `my-project`).
3. You can choose **Public** or **Private**.
4. You can check **Add a README file** to create a starter README.
5. Click **Create repository**.

**Copy the repository URL.** On the repository page, click the green **Code** button and copy the **HTTPS** URL. It will look like:

```
https://github.com/your-username/my-project.git
```

You will need this URL in the next sections.

---

### 1-2. Installation on Windows

**Installation.** Download and install the latest version of [Git](https://git-scm.com/downloads) for your operating system. The instructions below cover Windows first, then Linux and macOS.

> Running into an error? Jump to the [Troubleshooting](#4-troubleshooting) section at the end.

---

You can install Git on Windows using the `winget` package manager directly from Command Prompt (CMD) or PowerShell.

**Step 1: Check if winget is available.**

Open Command Prompt and run:

```cmd
winget --version
```

If you see a version number (e.g., `v1.8.1911`), `winget` is ready. Skip to Step 3.

If you see an error like `'winget' is not recognized`, `winget` is missing. Continue to Step 2.

**Step 2: Install winget (if needed).**

The easiest way to install `winget` is through the **Microsoft Store**. Search for **"App Installer"** and install it. This package includes `winget`.

**Step 3: Install Git using winget.**

In Command Prompt, run:

```cmd
winget install --id Git.Git -e --source winget
```

This downloads and installs the latest version of Git for Windows, including Git Bash and the Git GUI.

**Step 4: Restart your terminal.**

After installation finishes, **close and reopen Command Prompt**. This is required for the PATH changes to take effect.

**Step 5: Verify the installation.**

```cmd
git --version
```

You should see something like `git version 2.55.0`. If you do, Git is ready to use.

> **If winget is not available on your system**, you can download the standalone installer directly from the [official Git website](https://git-scm.com/downloads).

---

#### Updating Git on Windows

How you update Git depends on how you installed it.

**Method 1: If you installed Git with winget**

```cmd
winget upgrade --id Git.Git -e --source winget
```

**Method 2: If you installed Git using the official installer**

```cmd
git update-git-for-windows
```

> **Important:** `git update-git-for-windows` only works on Git versions **2.16.2 or later**. If your version is older, uninstall Git completely and install the latest version from the [official website](https://git-scm.com/downloads).

**After updating, verify the new version:**

```cmd
git --version
```

### 1-3. Installation on Linux and macOS

For Linux and macOS, follow the official installation guide:

🔗 **[Git Downloads and Installation Guide](https://git-scm.com/downloads)**

**Linux:** Use your distribution's package manager.

| Distribution       | Command                        |
| ------------------ | ------------------------------ |
| Debian / Ubuntu    | `sudo apt install git`         |
| Fedora             | `sudo dnf install git`         |
| CentOS / RedHat    | `sudo yum install git`         |
| Arch Linux         | `sudo pacman -S git`           |
| openSUSE           | `sudo zypper install git`      |

**macOS:** Install [Homebrew](https://brew.sh/), then run:

```bash
brew install git
```

To update later:

```bash
brew upgrade git
```

**Verify the installation on any platform:**

```bash
git --version
```

### 1-4. Configure Git

After installing Git, you need to tell it who you are.
Open your terminal and run these two commands, replacing the values with your own name and email:

```bash
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
```

**Verify your configuration:**

```bash
git config --list
```

You should see your name and email in the output.

### 1-5. Authentication: HTTPS vs SSH

When you push to GitHub, Git has to prove you are who you say you are. There are two ways to do this, and you only need one of them.

---

#### Setting up SSH (optional)

**Step 1: Check for existing keys.**

```bash
ls -al ~/.ssh
```

On Windows, run this in **Git Bash**. If you see `id_ed25519.pub` or `id_rsa.pub`, you already have a key — skip to Step 3.

**Step 2: Generate a new SSH key.**

Replace the email with the one on your GitHub account:

```bash
ssh-keygen -t ed25519 -C "your.email@example.com"
```

- Press **Enter** to accept the default file location.
- Enter a passphrase for extra security, or press **Enter** twice to skip.

This creates two files in `~/.ssh/`:

- `id_ed25519` — your **private** key.
- `id_ed25519.pub` — your **public** key. This is the one you give to GitHub.


**Step 5: Add the key to GitHub.**

1. Go to **github.com** and click your profile picture → **Settings**.
2. In the left sidebar, click **SSH and GPG keys**.
3. Click **New SSH key**.
4. Give it a title (e.g., "My laptop").
5. Paste your public key into the **Key** field.
6. Click **Add SSH key**.

**Step 6: Test the connection.**

```bash
ssh -T git@github.com
```

The first time, you will be asked to confirm the host fingerprint — type `yes`. If it works, you will see:

```
Hi your-username! You've successfully authenticated...
```

### 1-6. Submitting a Project with CMD

This section walks through submitting a project entirely from the command line. It works in **Command Prompt (CMD)** on Windows, and the same commands work in **Git Bash**, **PowerShell**, and the **Terminal** on Linux and macOS.

**Before you start:**

- Git is installed ([Section 1-2](#1-2-installation-on-windows))
- Git is configured with your name and email ([Section 1-5](#1-5-configure-git))
- You have the repository URL copied ([Section 1-1](#1-1-signing-up-on-github))

---

#### Scenario A: You Were Given a Repository to Clone

**Step 1: Navigate to where you want to work.**

Use `cd` to move to a folder you want to clone your repo in:

```cmd
cd "path"
```

**Step 2: Clone the repository.**

Paste the repository URL after `git clone`:

```cmd
git clone https://github.com/your-username/my-project.git
```

Git downloads the repository into a new folder with the same name.

**Step 3: Enter the repository folder.**

```cmd
cd my-project
```

This step matters. All the Git commands below only work if you are inside the repository folder.

**Step 4: Add your project files.**

Copy your finished files into this folder using File Explorer or Finder. Then check that Git can see them:

```cmd
git status
```

New files will appear in **red** under "Untracked files."

**Step 5: Stage your files.**

Staging tells Git which files to include in your next commit:

```cmd
git add .
```

The `.` means "everything in this folder and its subfolders." Run `git status` again — the files should now be **green** under "Changes to be committed."

**Step 6: Commit your changes.**

A commit is a saved snapshot with a message:

```cmd
git commit -m "Completed project"
```

**Step 7: Push to GitHub.**

```cmd
git push
```

This uploads your commit to GitHub. The first time you push, Git may open a browser window asking you to sign in to GitHub — complete the sign-in and it will remember you.

**Step 8: Verify.**

Open your repository on **github.com** in your browser and refresh the page. Your files and your commit message should be visible.

---

#### Scenario B: You Need to Create Your Own Repository

Use this if you already have a project folder on your computer and no repository on GitHub yet.

**Step 1: Create the repository on GitHub.**

Follow the steps in [Section 1-1](#1-1-signing-up-on-github) to create a new, empty repository. Copy the HTTPS URL.

**Step 2: Navigate to your project folder.**

```cmd
cd "path"
```

**Step 3: Initialize Git in this folder.**

```cmd
git init
```

This creates the hidden `.git` folder that turns a normal folder into a Git repository.

**Step 4: Stage and commit your files.**

```cmd
git add .
git commit -m "Initial commit"
```

**Step 5: Connect your folder to GitHub.**

```cmd
git remote add origin https://github.com/your-username/my-project.git
```

**Step 6: Set the branch name to `main`.**

```cmd
git branch -M main
```

**Step 7: Push your files.**

```cmd
git push -u origin main
```

The `-u` flag links your local branch to the remote one, so future pushes only need `git push`.

**Step 8: Verify.**

Refresh your repository page on **github.com**. Your files should now appear there.

---

#### Command Reference

| Command                       | What it does                                          |
| ----------------------------- | ----------------------------------------------------- |
| `cd folder-name`              | Move into a folder                                    |
| `cd ..`                       | Move up one folder                                    |
| `git clone <url>`             | Download a repository from GitHub                     |
| `git status`                  | Show which files have changed                         |
| `git add .`                   | Stage all changed files                               |
| `git add file.txt`            | Stage one specific file                               |
| `git commit -m "message"`     | Save a snapshot with a message                        |
| `git push`                    | Upload commits to GitHub                              |
| `git pull`                    | Download the latest changes from GitHub               |
| `git log --oneline -5`        | Show your last five commits                           |
| `git remote -v`               | Show which GitHub repository you are connected to     |

---

#### Common CMD Mistakes

- **Running Git commands in the wrong folder.** Run `git status`. If it says `not a git repository`, you are in the wrong place. Use `cd` to enter the cloned folder first.
- **Forgetting to push.** `git commit` only saves locally. Your changes will not appear on GitHub until you run `git push`.
- **Using `git add` without `.`** — `git add` alone does nothing. Use `git add .` or `git add filename`.
- **Forgetting the commit message.** `git commit` without `-m "message"` will open an editor that beginners often get stuck in. Always include the `-m` flag.

---

### 1-7. Ignoring Files with .gitignore

A `.gitignore` file tells Git which files **not** to track or commit. Use it to avoid committing passwords, `.env` files, caches, build output, and folders like `node_modules/`.

**Create it** in your repository root, named exactly:

```text
.gitignore
```

**Add patterns** — one per line:

```gitignore
# Files
secret.txt
.env

# Folders
node_modules/
__pycache__/
.vscode/

# Extensions
*.log
*.pyc

# OS junk
.DS_Store
Thumbs.db
```

Lines starting with `#` are comments.

**Check if it works:**

```bash
git status
git check-ignore -v path/to/file
```

Ignored files will not appear in `git status`.

**If the file is already tracked**, `.gitignore` will not affect it. Stop tracking it first:

```bash
git rm --cached filename
# or for a folder:
git rm -r --cached folder-name
```

**Commit and push:**

```bash
git add .gitignore
git commit -m "Add .gitignore"
git push
```

**Common mistake:** forgetting to commit `.gitignore` itself.

## 2. GitHub Desktop

GitHub Desktop is a free, official application from GitHub that provides a visual interface for Git. Instead of typing commands, you use buttons and menus.

**Suitable for beginners.** You can visually see your file changes and project history. Common actions like cloning, committing, and pushing are all buttons.

**Installation.** Download and install the latest version of [GitHub Desktop](https://github.com/apps/desktop). It includes Git, so you do not need to install Git separately (though having Git installed is still useful for the command line).

### 2-1. Submitting a Project with GitHub Desktop

**Step 1: Clone the project repository.**

Go to **File → Clone Repository**, paste the repository URL, choose a local folder, and click **Clone**.

**Step 2: Add your project files.**

Copy your project files into the cloned folder. GitHub Desktop will detect the new files automatically.

**Step 3: Review your changes.**

In the left panel, you will see a list of changed files. A green plus means a new file; a yellow dot means a modified file.

**Step 4: Write a commit message.**

At the bottom-left, type a short message like `"Completed project"`. Then click **Commit to main**.

**Step 5: Push to GitHub.**

Click the **Push origin** button at the top. This uploads your commit to GitHub.

**Step 6: Verify.**

Open the repository on **github.com** in your browser and confirm your files are there.

## 3. VS Code Integrated Git

Visual Studio Code has Git built directly into it. If you already use VS Code to write your code, you can commit and push without leaving the editor or installing another app.

**Prerequisite:** Git must be installed on your system (see [Section 1](#1-starting-with-git)). You should also be signed in to GitHub from VS Code.

### 3-1. Submitting a Project with VS Code

**Step 1: Open the project folder.**

Go to **File → Open Folder** and select the folder containing your project. This folder will become your repository.

**Step 2: Open the Source Control panel.**

Click the **Source Control icon** in the left sidebar (it looks like a branching line with dots). The keyboard shortcut is `Ctrl+Shift+G` (Windows) or `Cmd+Shift+G` (Mac).

**Step 3: Initialize the repository (first time only).**

If the folder is not already a Git repository, the panel will show a button that says **"Initialize Repository."** Click it. VS Code creates the hidden Git files and starts tracking the project.

**Step 4: Stage the files.**

Every new or changed file appears in the panel with a letter next to it:

- **U** = untracked (new)
- **M** = modified

To stage **one file**, hover over it and click the **plus (+)** icon.

To stage **all files**, click the **plus** icon next to the "Changes" heading, or use the **Stage All Changes** button.

Staging tells Git: "These are the files I want to include in my next commit."

**Step 5: Write a commit message and commit.**

Type a short message in the text box at the top of the Source Control panel, such as `"Completed project"`. Then click the **checkmark icon** (or press `Ctrl+Enter`) to commit.

**Step 6: Push to GitHub.**

Committing only saves changes locally. To submit your work, click the **Push** button or **Sync Changes** button that appears after committing. If this is the first time, VS Code may show **"Publish Branch"** instead, which creates the remote repository on GitHub and pushes at the same time.

**Step 7: Verify.**

Open the repository on **github.com** in your browser and confirm your files are there. That is the final check that your submission worked.

### 4-1. Installation & Setup

#### ❌ `'git' is not recognized as an internal or external command`

Installation may have been successful, but Windows cannot find Git. Work through these causes in order.

**Cause 1: You never restarted your terminal after installing Git.**

The PATH is updated during installation, but terminals that are already open do not see the change. **Close and reopen CMD**, then try `git --version` again.

**Cause 2: Git was installed without being added to the system PATH.**

1. Open the Start menu and search for **"Edit the system environment variables"**.
2. Click **"Environment Variables"**.
3. Under **"System variables"**, find the variable called **`Path`** and click **"Edit"**.
4. Click **"New"** and add the path to Git's `cmd` folder. Example: `C:\Program Files\Git\cmd`
5. Click **OK** on all windows to save.
6. **Close and reopen your terminal** for the change to take effect.

---

#### ❌ `'winget' is not recognized`

`winget` is not installed or not on your PATH.

**Fix:**

1. Open the **Microsoft Store** and search for **"App Installer"**.
2. Install or update it. This package includes `winget`.
3. Close and reopen your terminal, then run `winget --version` again.

> **Note:** `winget` requires Windows 10 version 1809 or later. On older versions of Windows, download Git directly from the [official website](https://git-scm.com/downloads) instead.

---

#### ❌ `git update-git-for-windows` fails or says the command is unknown

This command only works on Git versions **2.16.2 or later**.

**Fix:** Uninstall Git completely and install the latest version from the [official website](https://git-scm.com/downloads).

---

#### ❌ Git installed, but `git --version` shows an old version

You may have more than one version of Git installed, and the terminal is picking up the wrong one.

**Fix:** Open a **new** Command Prompt and run:

```cmd
where git
```

or in PowerShell:

```cmd
where.exe git
```

If it prints more than one path, the first one is what your terminal is using. You can either remove the older installation, or reorder your system `Path` variable so the newer Git path appears first.

---

### 4-2. Git Command Problems

#### ❌ `fatal: not a git repository (or any of the parent directories): .git`

You are running a Git command in a folder that has not been initialized as a Git repository.

**Fix:** Make sure you are in the correct folder. If you just cloned the repository, `cd` into the cloned folder first. If you need to start tracking this folder, run:

```cmd
git init
```

---

#### ❌ `fatal: destination path 'project-name' already exists and is not an empty directory`

You are trying to clone a repository into a folder that already contains files.

**Fix:** Either delete or rename the existing folder, or clone into a new folder name:

```cmd
git clone <repository-url> new-folder-name
```

---

#### ❌ `error: failed to push some refs` / `Updates were rejected`

This happens when the remote repository has changes that you do not have locally. This is common when you edit files directly on GitHub and then try to push from your computer.

**Fix:** Pull the remote changes first, then push again:

```cmd
git pull
git push
```

If you see a message about `unrelated histories`, or you are sure you want to overwrite the remote with your local version (use with caution):

```cmd
git push --force
```

> **Warning:** `--force` overwrites the remote history.

---

#### ❌ `error: pathspec 'file.txt' did not match any file(s) known to git`

You tried to add or commit a file that Git cannot find, usually because the file name is misspelled or the file is in a different folder.

**Fix:** Check the spelling and the current folder. Use `git status` to see what Git can actually see.

---

#### ❌ `git status` shows nothing to commit, but I changed files

**Cause 1:** Your changes are already committed. Run `git log --oneline -5` to see your recent commits.

**Cause 2:** You are in the wrong folder. Run `pwd` (Linux/macOS) or `cd` (Windows) to check where you are.

**Cause 3:** The files are listed in `.gitignore`, so Git is intentionally ignoring them. Open `.gitignore` and check if your file's name or extension is listed there.

---

### 4-3. Authentication Problems

#### ❌ `remote: Support for password authentication was removed`

GitHub no longer accepts your account password over HTTPS. You will see this when Git tries to use a saved password instead of a browser sign-in or token.

**Fix:** Clear the stored credential so Git prompts you to sign in again.

- **Windows:** Open **Credential Manager** → **Windows Credentials** → remove the entry named `git:https://github.com`.
- **macOS:** Open **Keychain Access** → search for `github.com` → delete the matching entry.

Then push again — Git will open a browser window for sign-in.

Alternatively, switch to SSH. See [Section 1-4](#1-4-authentication-https-vs-ssh).

---

#### ❌ `Permission denied (publickey)` when using SSH

GitHub rejected your SSH key. There are four common causes — work through them in order.

**Cause 1: No SSH key has been added to GitHub.**

Follow [Section 1-4](#1-4-authentication-https-vs-ssh) to generate a key and add the public half to your account.

**Cause 2: The key is not loaded into the SSH agent.**

```bash
ssh-add -l
```

If this prints *"The agent has no identities,"* add your key:

```bash
ssh-add ~/.ssh/id_ed25519
```

**Cause 3: Your remote is still using HTTPS.**

```bash
git remote -v
```

If the URL starts with `https://`, switch it:

```bash
git remote set-url origin git@github.com:your-username/my-project.git
```

**Cause 4: You need to see which key is being offered.**

```bash
ssh -vT git@github.com
```

The `-v` flag prints verbose output showing which key Git tried and where it failed.

---

#### ❌ `remote: Repository not found`

This usually means one of three things:

- **The URL is wrong.** Double-check the repository link on GitHub.
- **The repository is private** and you are not authenticated. Make sure you are signed in — Git will prompt a browser sign-in on first push.
- **You do not have access** to the repository. Ask the repository owner to confirm you have access.

---

### 4-4. Commit & Push Problems

#### ❌ I committed my changes but they are not visible on GitHub

You probably forgot to **push**. Committing saves changes only on your own computer.

**Fix:** Run:

```cmd
git push
```

Then open the repository on github.com and refresh the page to confirm the files are there.

---

#### ❌ `Please tell me who you are` / `Author identity unknown`

You have not set your Git username and email yet.

**Fix:** Follow [Section 1-5](#1-5-configure-git).

---

#### ❌ I committed the wrong files (or a password, or a large file)

If you have not pushed yet, you can undo the commit while keeping your files:

```cmd
git reset --soft HEAD~1
```

This removes the last commit but keeps your changes staged so you can re-commit correctly.

---

#### ❌ `warning: LF will be replaced by CRLF`

This is a line-ending warning, not an error. It appears on Windows when Git converts line endings. **You can safely ignore it.**

If the warning bothers you, you can silence it with:

```cmd
git config --global core.autocrlf true
```

---

#### ❌ My files are not showing up on GitHub, but `git status` says they are committed

**Cause 1:** You committed but did not push. Run `git push`.

**Cause 2:** You pushed to a different branch than the one you are supposed to use. Run `git branch` to see your current branch, and push to the correct one:

```cmd
git push origin main
```

**Cause 3:** The files are in `.gitignore`. See [Section 1-7](#1-7-ignoring-files-with-gitignore).

---

### 4-5. GitHub Desktop Problems

#### ❌ GitHub Desktop does not detect my new files

**Fix:** Make sure the files are inside the repository folder, not next to it. In GitHub Desktop, click **Repository → Show in Explorer/Finder** to see exactly which folder is being tracked.

**Fix:** Click **Repository → Refresh** (or press `F5`) to force a rescan.

---

#### ❌ The "Push origin" button is missing or greyed out

This usually means there is nothing to push — either you have not committed anything yet, or everything is already pushed.

**Fix:** Check for uncommitted changes in the left panel. If there are none, and the top says "No local changes," you are up to date.

---

#### ❌ I see "Publish branch" instead of "Push origin"

This is normal the first time you push a new repository. Click **Publish branch** — it creates the repository on GitHub and pushes your commit in one step.

---

### 4-6. VS Code Problems

#### ❌ The Source Control icon shows no changes

**Cause 1:** You have not saved your files. VS Code only tracks saved files. Press `Ctrl+S` on each file.

**Cause 2:** The folder is not a Git repository. Follow [Section 3-1, Step 3](#3-1-submitting-a-project-with-vs-code) to initialize it.

**Cause 3:** The folder you opened is not the repository root. Close the folder and open the correct one with **File → Open Folder**.

---

#### ❌ The Push button does not appear after committing

This usually means the repository is not yet connected to GitHub.

**Fix:** VS Code should show a **"Publish Branch"** button instead. Click it and choose whether the repository should be public or private.

If neither button appears, open a terminal in VS Code (``Ctrl+` ``) and run:

```cmd
git remote -v
```

If this prints nothing, there is no remote. Ask the repository owner for the correct repository URL, then run:

```cmd
git remote add origin <repository-url>
git push -u origin main
```

#### ❌ VS Code asks me to sign in to GitHub repeatedly

**Fix:** Open the Command Palette (`Ctrl+Shift+P`), run **"GitHub: Sign Out"**, then run **"GitHub: Sign In"** and complete the browser flow.

If the problem continues, check that your system clock is accurate, and make sure you are not using a VPN or proxy that might interfere with the OAuth flow.
